# AGENTS.md — Kelid (کلید)

Instructions for every AI coding agent (Claude Code, Codex, Cursor, Copilot, Gemini…) and the humans driving them.
Keep this file short: it is loaded into every session. Details live in the files it points to.

## What this is
Kelid is a subscription SaaS for Iranian real-estate offices (املاکی‌ها): property files (sale / rent / full-mortgage),
clients, visits, showing files to customers. One React codebase ships as a Windows app (Electron), a web app and a phone PWA.
**Offline-first**: every device has its own local SQLite DB; a server + sync arrives in phase 2.
Users are often older and non-technical → the UI must stay calm, obvious, fast and premium. Simplicity beats features.

## Hard rules
**Data**
- UI never runs SQL. Pages read through `useQuery(key, s => s.method())` and write through `useStore()` methods (`apps/web/src/data.tsx`).
- `KelidStore` (`packages/core/src/store.ts`) is the contract. A new method must be implemented in **both** `SqlStore` and `MemoryStore`, with a test.
- Every mutation in `SqlStore` = one `driver.transaction([...])` containing the row change **and** an `outbox` insert, then `this.emit()`. The outbox is the sync log (each row gets an HLC via `this.outbox()`) — never skip it.
- Deletes are soft (`deleted = 1`) so they can be undone and synced.
- Schema changes: **append** a new entry to `migrations` in `packages/core/src/sql/schema.ts`. Never edit a shipped migration.
- Text that users search goes through `normalizeForSearch` (Arabic ي/ك, ZWNJ, digits, diacritics).

**Server**
- Office data is read and written only inside `withOffice(pool, officeId, db => …)` (`apps/server/src/db.ts`); every table gets `enable` + `force row level security` and a policy on `kelid_office()` (a test fails otherwise).
- Vendor (admin panel) access goes only through `withVendor` and the `kelid_vendor()` policies; never give the vendor office data tables.
- Auth tables (`users`, `devices`, `otp_codes`, `signup_tickets`, `device_tickets`, `invites`) are global on purpose (no office before login) and only `auth/` (`routes.ts`, `team.ts`) touches them, always filtered by the caller's own `office_id`; codes and tokens are stored as hashes only, passwords as scrypt hashes (`auth/password.ts`). SMS goes through `SmsSender` (`auth/sms.ts`).
- The runtime DB role is never superuser/BYPASSRLS and doesn't own the tables; migrations run with the owner role. 5xx responses never include internal error text.

**UI / UX**
- All user-facing text is Persian; the app is `dir="rtl"`. Show numbers with `toFaDigits`, parse input with `toEnDigits`. Money via `formatToman`, dates via `format.ts` (Persian calendar, Asia/Tehran).
- Colors, radii, spacing only from tokens in `packages/ui/src/kelid.css` (`var(--…)`); dark mode must work. Font: Vazirmatn only, self-hosted.
- The «پلاک» is the only color code: green = sale, mustard = rent, blue = full mortgage. Don't invent new semantic colors.
- No full page reloads, ever. Navigate with `<Link viewTransition>` / `navigate(to, { viewTransition: true })`; no `window.location`, no `<a href>` for internal routes. Exception: sidebar and phone tab-bar switches are instant (no view transition) so tabs never feel laggy.
- No spinners. Loading = `useSlow(pending)` + `Skeleton`/`PageSkeleton` (shows only after 120 ms). Cached data shows instantly when returning to a page.
- Destructive actions: do them immediately and offer undo via `useToast()(text, { label: 'برگرداندن', run })` instead of confirm dialogs (exception: bulk/irreversible actions get an inline confirm).
- Motion comes from `motion.css` classes (`enter`, `stagger`, `lift`, `pop-in`…) and must respect `prefers-reduced-motion`.
- Every icon button needs `aria-label`; keyboard must work (Ctrl+K search, Ctrl+N new file, Esc closes overlays).

**Platform / security**
- Never load anything from external CDNs or Google Fonts (blocked/unstable in Iran). Bundle all assets.
- Electron renderer stays sandboxed: `contextIsolation`, `sandbox`, no `nodeIntegration`. The renderer reaches native code **only** through `window.kelid` from `preload.ts`; add IPC channels there and in `database.ts` with input validation.
- The desktop DB key is protected by Windows DPAPI (`safeStorage`) — never log it, never write it in plain text.
- Desktop updates install only when signed with the release key (`apps/desktop/src/updateSignature.ts`); ship releases through `npm run release -w @kelid/desktop` (docs/ARCHITECTURE.md → Releasing). The private key never enters the repo.
- No secrets in the repo. Config goes in `.env` (git-ignored); document new variables in `.env.example`.
- Native npm modules must ship prebuilt binaries (no Visual Studio / node-gyp on dev machines). npm 12 blocks install scripts unless listed under `allowScripts` in the root `package.json`.

**Code style**
- TypeScript strict with `noUncheckedIndexedAccess`; no `any` without a reason in a comment.
- ESLint must pass with zero warnings in CI. Prettier (`.prettierrc.json`) formats **new** files; don't reformat existing files inside a feature PR (merge conflicts for the other person) — a repo-wide `npm run format` gets its own PR when no branches are open.
- Identifiers in English; comments in Persian, short, explaining *why* (match surrounding code).
- Match existing patterns before adding libraries. Ask the owner before adding a dependency.

## Known gotchas
- Web DB (OPFS) can be open in **one browser tab at a time**; other tabs fall back to an in-memory DB (`where: 'locked'`).
- Electron holds a single-instance lock: close `npm run dev:desktop` before launching a packaged build, or it exits silently.
- `npm install` warns that `better-sqlite3-multiple-ciphers`' `node-gyp rebuild` script was blocked — expected; never approve it (prebuilt N-API binaries are used).
- `electron-builder` must keep `npmRebuild: false` (prebuilt SQLCipher binaries; rebuild needs Visual Studio).
- Vite and Vitest must stay on the same Vite major (currently 8) or tests fail with `Missing field moduleType`.
- `Intl` date parts order differs between engines: build Persian dates with `formatToParts`, never by string-splitting.

## Team workflow (two people + their agents work in parallel)
- **First time on a machine:** `npm run setup` (installs deps, git hooks, graphify, runs checks).
- **Tasks live in GitHub Issues** (`danialmesbahi/kelid`), grouped by phase milestones; overview + suggested split in `docs/ROADMAP.md`.
- Project skills for Claude Code: `/kelid-task` (claim issue → branch → context), `/kelid-sync` (merge main + conflict rules), `/kelid-ship` (verify → PR). Other agents: follow the same steps from `.claude/skills/*/SKILL.md`.
- One issue = one branch `<feat|fix|chore>/<issue#>-<slug>` = one small PR with `Closes #N`. Assign the issue to yourself before starting; never take an issue assigned to someone else.
- **Never push to `main`** (a local pre-push hook blocks it; the free plan has no branch protection). Merge = squash, after CI is green and the other person approved.
- Commit messages: short imperative English (`feat: add listing editing`). Never commit `node_modules`, `dist*`, `release/`, `.env`, DB or key files.
- Conflicts: migrations keep main's order and append yours after; `package-lock.json` take main's then `npm install`; `graphify-out/` take main's then `graphify update .`.
- The design canvas (all screens incl. phone, signup, plans, admin) is linked in `docs/ROADMAP.md`; build new screens from it, not from imagination.
